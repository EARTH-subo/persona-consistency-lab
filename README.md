# persona-consistency-lab

> **角色资料工程 × 本地混合检索 × 一致性评测**
> 把「像不像这个角色」从主观感觉，拆成**可溯源、可检索、可打分**的工程问题。

个人项目 · 2026.10 · 角色：《崩坏：星穹铁道》姬子（星穹列车领航员）

`Python` · `SQLite FTS5` · `ONNX BGE` · `RRF` · `LangChain` · `DeepSeek`

## 一、这个项目在做什么

给一个游戏角色做**可运行的角色扮演 Agent**，并给出**可量化的人设一致性评测**。

核心问题只有一个：当一个角色设定复杂、且有大量官方未明说的暗线时，怎么判断模型「像不像」她？

我的处理方式是把这件事拆成三层：

1. **角色资料工程**——把散落在官方角色详情、角色故事、角色语音、官方影像里的信息，整理成一份带出处的人设卡，并且严格区分「官方事实」与「演绎约定」；
2. **检索增强**——把官方语料做成可检索的本地库，回答前先检索原文，减少编造；
3. **一致性评测**——自建题集与判据，用 LLM 裁判逐题打分，并**用失分模式反推规则、回填人设卡**。

第 3 步的闭环是这个项目真正想展示的东西：不是「我做了个 Agent」，而是「我发现它哪里不像、为什么不像、然后怎么改」。

## 三、三个核心方法

### 1. 人设卡工程：把「官方事实」和「演绎约定」分开

角色扮演类 Agent 最容易出的问题是**把二创当官方**。人设卡因此分两层：

- **官方事实层**：只收官方原文，逐条标注出处（角色详情 / 角色故事 / 角色语音 / 官方影像）；官方没明说的，标 `【官方未明说】`，**不替官方补全**。
- **演绎约定层**：面向扮演的行为约束（决策优先级、状态机、冲突裁决表、评测说明），明确标注为**演绎**，不得当作官方事实说出口。

这个分离直接决定了两件事能不能做：一是评测时能判断「这是漂移」还是「这是合理的二创」；二是 Agent 被追问时知道哪些话不能说。

### 2. 敏感话题的「三级披露梯度」+「三级兜底」

角色有若干**暗线话题**（涉及剧透与未明说设定）。处理方式不是简单拒绝，而是分级：

| 追问次数 | 允许的披露 |
|---|---|
| 第一次 | 只做无信息量的回避，禁止点名关键词 |
| 第二次 | 允许一句无主语暗示，仍不点名 |
| 第三次及以后 | 允许有限披露，但仍禁止剧透结局 |

同时设「三级兜底」防止幻觉：**本地检索 → 联网回查 → 不编造**。片段不足以定论时，宁可说不知道，也不拼凑。

这条规则是踩坑踩出来的：测试中模型一度把「冒充角色亲属的 NPC」当成真亲属——暴露出「碎片拼凑」风险，于是把「片段不足不得拼凑」写成了硬约束。

### 3. 一致性评测：三轴题面 + 四项判据

- **题面三轴**：8 个维度（身份头衔 / 世界观口径 / 语料口吻 / 车务日常 / 关系态度 / 沉底层 / 战斗高压 / 边界纪律） × 8 个场景（观景车厢 / 派对车厢 / 维修机库 / 战斗与探索 / 异星开拓见闻 / 沉底场景 / 航路会议 / 越界盘问），每格 1 题，强度（D1 直接提问 / D2 诱导漂移 / D3 高压越界）按格子性质指派。
- **每题四项判据**：`expect`（期望要点 ≥3）、`must_not`（禁止项 ≥3）、`must_include_any`（应含项 ≥3）、`bonus_any`（加分项 ≥2），并附 `basis` 依据来源。
- **依据可溯源率 100%**：每条判据都指向〔官方出处〕或〔演绎条款 9.x〕，没有凭空依据。

## 四、系统架构

```
用户提问
   │
   ▼
jizi_agent.py
   ├── 读取 姬子_人设卡_v2.txt  → 系统提示词（扮演纪律 + 事实/演绎两层）
   ├── 调用 rag/retrieve.py（子进程）
   │       ├── FTS5 全文检索（jieba + 专有名词表）
   │       ├── BGE 向量检索（onnxruntime + numpy 余弦）
   │       └── RRF 融合去重 → top-4 原文片段
   └── 注入「参考资料」块 → ChatDeepSeek 生成回复
```

**注入纪律**：检索片段被明确标注为「参考资料」，与档案冲突时以人设卡为准；片段不足时不得拼凑。

## 六、评测结果摘要

64 题，平均 **4.16 / 5**。

| 档位 | 含义 | 题数 |
|---|---|---|
| 5 | 完全在角色内 | 28 |
| 4 | 基本一致 | 27 |
| 3 | 轻微漂移 | 2 |
| 2 | 明显漂移 | 5 |
| 1 | 出戏 / OOC | 2 |

**按压力强度**（最关键的规律）：

| 强度 | 平均分 |
|---|---|
| D1 直接提问 | 4.52 |
| D2 诱导漂移 | 3.96 |
| D3 高压越界 | 3.83 |

> **压力越大，分数越低。** 这条规律说明：角色扮演的失效不是随机的，而是被「压力」和「敏感话题」系统性地触发。

**主要失分模式**（三类）：

1. 被激时多说——在越界盘问下吐露沉底层信息；
2. 被迫排序时让步——被要求「必须点名一个」时，前半句拒绝、后半句仍完成了排序；
3. 场景知识不足——对特定场景的设定掌握不够，回答偏说教或漏掉关键口径。

详细的逐题分析与从失分回填规则的完整过程，见 [`docs/评测报告.md`](docs/评测报告.md)。

## 七、从失败里长出来的规则

这个项目最有价值的部分，是**失分 → 归因 → 回填规则**的闭环。举例：

| 测试暴露的问题 | 回填的规则 |
|---|---|
| 模型把「冒充亲属的 NPC」当成真亲属 | 新增硬约束：检索片段不足时不得拼凑结论 |
| 元层面出戏（被要求「以 AI 身份讲设定」时照做） | 扮演纪律第 1 条：绝不提及人设卡 / 系统提示 / AI / 模型 |
| 战斗场景被要求喊「中二长口号」时照做 | 语气锚定官方非战斗语料：短句、不铺陈抒情 |
| 每条回复都提咖啡，把咖啡当回避或收尾 | 明确禁用：咖啡不得作为回避手段或万能结尾 |
| 回复末尾总追加「你还想知道什么」 | 明确禁用引导性追问，回复默认以陈述句收尾 |

## 八、快速开始

```bash
pip install -r requirements.txt
```

在仓库根目录创建 `.env`：

```
DEEPSEEK_API_KEY=sk-xxxx
```

运行 Agent（交互式）：

```bash
python jizi_agent.py
```

单轮提问：

```bash
python jizi_agent.py "给我来杯咖啡"
```

> 说明：Agent 会调用 `rag/retrieve.py` 做本地检索。**本仓库不含语料与索引数据**（原因见第九节），因此开箱状态下检索会返回空、Agent 直接以人设卡作答；要启用检索，需先按 `rag/` 下的脚本重建语料与索引。

重建语料与索引：

```bash
cd rag
python crawl_himeko_tasks.py     # 抓取任务清单
python build_himeko_corpus.py    # 抓取语料
python filter_corpus.py          # 清洗过滤
python build_fts_index.py        # 建全文索引
python build_vector_index.py     # 建向量索引
```

跑一致性评测：

```bash
cd 人设一致性测试
python run_persona_test.py
```

## 十、已知限制

1. 语料来自第三方 wiki 的官方文本转录页，覆盖度受该站收录范围限制。
2. 抓取工具以关键词发现页面；不含关键词的页面无法被自动发现。
3. 向量检索使用 numpy 暴力余弦，数据量增大后需改用索引库（如 HNSW）。
4. 评测的 LLM 裁判存在自身偏差，当前未做裁判效度审计（这是下一步计划）。
5. 检索与生成分属不同 Python 环境（检索依赖较重），通过子进程调用衔接。
